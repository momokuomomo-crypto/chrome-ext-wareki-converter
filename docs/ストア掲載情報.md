## 概要（132文字以内）

> 西暦と和暦を日付単位で相互変換します。改元のあった年は境界日を注記で示し、昭和64年1月8日のような存在しない和暦は作りません。外部送信なし。

## 詳細な説明

```
西暦と和暦を、日付単位で相互に変換します。

■ 改元の境界を教えます

同じ1989年でも、1月7日までは昭和64年、1月8日からは平成元年です。
このアプリは、改元のあった年に必ず境界日を注記で示します。

  入力：1989/1/8
    平成元年1月8日
    1989年1月8日
    ※ 1989年は1月7日までが昭和64年、1月8日からが平成元年

■ 存在しない和暦を作りません

「昭和64年1月8日」は実在しません。この日は平成元年1月8日です。
入力された場合は期間外であることを示したうえで、正しい日付を併記します。

■ 年だけでも変換できます

  1901 → 明治34年
  1989 → 昭和64年（1月1日〜1月7日）／平成元年（1月8日〜12月31日）

改元のあった年は、どちらか片方に丸めず両方を並べます。

■ 使い方は2通り

・ツールバーのアイコンから、日付を直接入力する
・ページ上の日付を選択して右クリックする

■ 表記ゆれを吸収します

1989/1/8、1989-1-8、1989.1.8、19890108、1989年1月8日、平成元年1月8日、
H1.1.8、H元/1/8、全角数字、「生年月日：1989年1月8日」、「1989年1月8日（日）」
これらはすべて同じ結果になります。

■ プライバシー

・外部への通信を一切行いません
・入力した日付を保存しません
・ページの内容を読み取る権限を要求しません

保存するのは「主に表示する形式（和暦／西暦）」の設定だけで、
これはお使いのブラウザ内にのみ保存されます。

■ 対応範囲

1873年1月1日（明治6年1月1日）以降に対応します。
明治5年以前は旧暦のため、元号年から西暦への機械換算が成立しません。
```

## 単一用途の説明

> 日付の西暦・和暦相互変換のみを行います。ポップアップへの入力と、選択テキストの右クリックという 2 つの入力経路がありますが、どちらも同じ変換機能への入口であり、用途は 1 つです。

---

## 権限の正当性

3 つだけを要求する。`host_permissions`・`activeTab`・`scripting` は要求しない。

| 権限 | 記入内容 |
|---|---|
| `contextMenus` | ページ上で選択した日付を右クリックから変換するため、コンテキストメニューへ項目を 1 つ追加します。 |
| `storage` | 「主に表示する形式（和暦／西暦）」の設定を保存し、次回起動時に復元するために使用します。保存するのはこの設定のみで、入力された日付や変換結果は保存しません。 |
| `notifications` | 右クリックから変換した結果を通知で表示するために使用します。通知が無効な場合は、拡張機能アイコンにバッジを出してポップアップへ誘導します。 |

**ホスト権限を要求しない理由**（欄があれば記入）

> ページの内容を読み取る必要がないためです。右クリック経路では Chrome が提供する選択テキスト（`info.selectionText`）のみを受け取り、ページへスクリプトを挿入しません。

## リモートコード

> 使用しません。

すべてのコードは拡張機能パッケージに同梱されています。`eval` と `new Function` を使用せず、外部 URL への参照もありません。ビルド時の `npm run verify` でこれらの混入を機械的に検査しています。
